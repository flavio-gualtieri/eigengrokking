SPECTRAL ANALYSIS METHODOLOGY
==============================
Hessian spectral density estimation for grokking runs (e.g. modular addition,
p=97, 1-2 layer transformer). Written after implementing the six
instrumentation requirements below; each section maps to one of them.

This replaces the previous ad hoc metrics (phi_1_moment, phi_2_moment,
eig_mass_gt1, phi_pos_neg_ratio) with a defined, reproducible methodology.


1. HVP VIA DOUBLE-BACKWARD (TRUE HESSIAN, NOT GGN)
---------------------------------------------------
Unchanged from before -- it was already correct. `Eigenthings.hvp()` in
analysis/eigenthings.py uses Pearlmutter's double-backward trick:

    grads = autograd.grad(loss, params, create_graph=True)
    gv    = sum((g * v).sum() for g, v in zip(grads, probe_direction))
    Hv    = autograd.grad(gv, params)

`loss` is the real scalar loss from a full forward pass, so this backprops
through the actual network map end to end -- it is the true Hessian, not a
Gauss-Newton/Fisher surrogate that would zero out negative curvature. The
signed spectrum (negative_mass, below) depends on this.


2. STOCHASTIC LANCZOS QUADRATURE (SLQ)
----------------------------------------
analysis/eigenthings.py: `Eigenthings.lanczos()` / `estimate_density()`.

  - Rademacher probes: `rademacher_probe()` draws +/-1 entries (previously
    Gaussian). Sampled with a CPU torch.Generator, then moved to the model's
    device -- CUDA/MPS generators aren't interchangeable, so this keeps the
    probe sequence identical regardless of accelerator.
  - m = spectral_m Lanczos steps per probe (default 90, config range 80-100).
  - k = spectral_k probes (default 16, in the 10-20 range).
  - Full reorthogonalization: every new Lanczos vector is Gram-Schmidt'd
    against every previous one in the run (`for qi in Q: w -= dot(qi,w)*qi`),
    not just the last one or two. Lanczos loses orthogonality after a few
    dozen steps without this, silently corrupting the density estimate --
    this is why full reorthogonalization is non-negotiable at m=90.

`estimate_density()` returns a `SpectralEstimate` with both the
probe-averaged KDE-smoothed density (`density`, `t_grid` -- used only for the
plotted spectrum PNGs) and the raw per-probe Ritz nodes/weights
(`probe_nodes`, `probe_weights`). All eight scalar observables (section 4)
are computed from the raw per-probe data, not the smoothed curve, since
KDE bandwidth otherwise biases tail-sensitive quantities like top_eig and
outlier detection.


3. FIXED PROBE BATCH, IDENTICAL ACROSS CHECKPOINTS
-----------------------------------------------------
Two things are now fixed per run, both previously drifting:

  - Data batch: training/loop.py samples one fixed batch
    (`spectral_batch_size`, default 512) once, before the training loop
    starts, via a `shuffle=False` DataLoader over the training set. Every
    spectral snapshot in the run computes its loss on this exact batch.
    Previously the Hessian's loss was computed on whatever live shuffled
    minibatch happened to be current at that step.
  - Probe vectors: `estimate_density(..., probe_seed=cfg.seed)` reseeds a
    fresh `torch.Generator` on every call. Calling it repeatedly with the
    same `probe_seed` (once per checkpoint) draws bit-identical probes every
    time. Only the model parameters differ between two spectral snapshots in
    the same run -- probe-sampling noise and batch-to-batch variation are
    both eliminated as confounds.


4. OBSERVABLES PER CHECKPOINT
--------------------------------
analysis/spectral_observables.py. All eight are computed from the raw pooled
per-probe (node, weight) atoms: `probe_nodes`/`probe_weights` from k probes
are concatenated with each probe's weights divided by k, giving one discrete
distribution that approximates the normalized spectral measure
(1/n) sum_i delta(t - lambda_i).

  top_eig         Largest pooled Ritz node across all k probes. Precise
                   because it comes from raw data, not the KDE curve (KDE
                   bandwidth would blur/underestimate the tail).

  bulk_edge       median(nodes) + 5 * MAD(nodes), a robust (non-Gaussian-
                   assuming) outlier threshold. MAD is scaled by 1.4826 to be
                   consistent with a normal-distribution standard deviation.
                   Chosen over a fixed threshold (the old mass_above_thresh
                   at lambda=1.0) or a Marchenko-Pastur-style edge, which
                   needs an aspect ratio that isn't well-defined for a
                   Hessian.

  outlier_count   Nodes above bulk_edge, then clustered: consecutive sorted
                   outlier nodes closer than `resolution` (5% of |top_eig|)
                   are merged into one cluster. Needed because Lanczos
                   rediscovers the same true outlier eigenvalue as several
                   near-identical Ritz values across different probes/steps
                   -- without merging, outlier_count would just count Ritz
                   values, not distinct eigenvalues.

  trace           Hutchinson-via-Lanczos: n_params * sum(weight * node) over
                   the pooled distribution. This is exact in expectation for
                   Rademacher probes (E[v^T H v] = tr(H)) and follows
                   directly from the SLQ quadrature -- no extra HVPs needed
                   beyond what SLQ already computes.

  spectral_entropy /
  effective_rank   Shannon entropy of the pooled |lambda| distribution,
                   histogrammed with the same `resolution` bin width used for
                   outlier clustering (keeps both quantities tied to one
                   consistent length scale rather than an arbitrary second
                   bin choice). effective_rank = exp(spectral_entropy) --
                   how many eigen-directions have non-negligible curvature
                   magnitude, regardless of sign.

  negative_mass   Margin-thresholded: sum of pooled weights where
                   node < -margin_c * |top_eig| (default margin_c=0.05), not
                   raw node < 0. Validation on a tiny MLP with an exact
                   reference Hessian (reports/spectral_validation.md) found
                   the raw-zero threshold needed m>=200 to converge, because
                   Lanczos produces spurious near-zero negative Ritz values
                   that a raw threshold wrongly counts as curvature evidence
                   -- 193 of 1026 exact eigenvalues on that fixture sat in
                   the now-excluded [-epsilon, 0) noise band. Margin-
                   thresholded, the same observable converges by m~30-50.
                   Replaces the old mislabeled `phi_pos_neg_ratio` key, which
                   actually held a mirror-asymmetry statistic, not a
                   negative-mass or pos/neg-ratio quantity.

  conditioning    top_eig / bulk_edge, a cheap conditioning proxy: how far
                   the extreme eigenvalue sits above the bulk.

Error bars over probes: `compute_spectral_observables_with_stderr()` returns
(point_estimate, stderr). `point_estimate` pools all k probes (least biased).
`stderr` is the standard error of the mean across k *single-probe* estimates
of the same quantity -- i.e. how much each number would move under a fresh
draw of probes. This is not the literal SEM of every point estimate (e.g.
top_eig is a pooled max, not a mean of per-probe maxes, so pooled-max >=
mean-of-maxes always) -- it's the standard, pragmatic uncertainty proxy used
throughout, and it costs nothing extra: no new HVPs, just re-running the same
observable computation on each probe's data alone.

Every field gets a `<name>` and `<name>_stderr` entry in the training
history and the saved npz. Single-run plots (project_io/graphing.py,
PLOT_VARIANTS) draw the stderr as a shaded +/-1 band via matplotlib
fill_between (and as `error_y` in the Plotly variant).


5. GEOMETRIC-THEN-DENSE ADAPTIVE LOGGING
-------------------------------------------
training/spectral_schedule.py: `SpectralSchedule`.

Default cadence is geometric: each logged step is `spectral_growth`x
(default 1.15) further out than the last, so early training is sampled
coarsely without spending the whole compute budget there. The schedule
tracks the train/test accuracy gap (updated once per eval, from
train/test accuracies the loop already computes) and switches to a dense
fixed stride (`spectral_dense_stride`, default 100 steps) whenever
|d(gap)/d(step)| >= `spectral_gap_rate_threshold` (default 1e-4) -- i.e.
during the grokking transition itself. It reverts to geometric spacing once
the rate drops back down. The geometric counter keeps advancing internally
even while dense mode is active, so there's no stale catch-up log when
exiting a long dense phase.

This replaced a single fixed-modulo trigger (`spectral_every`, now removed
from ExperimentConfig) that spent equal resolution everywhere regardless of
whether anything was happening.

Tuning note: `spectral_gap_rate_threshold` is dataset/hyperparameter
dependent (it's an absolute rate of accuracy-gap change per step) and will
need empirical adjustment per task -- there's no universal value. Start by
running with `run_spectral=True` and eyeballing where grokking happens in
the accuracy curves, then tune the threshold so dense logging brackets that
window.


6. ERROR BARS: PROBES (WITHIN A RUN) AND SEEDS (ACROSS RUNS)
-----------------------------------------------------------------
Within-run (probes): section 4, above -- every observable carries a stderr
computed from the same k probes at no extra HVP cost.

Across-run (seeds): configs/sweeps.py adds `with_seeds(base_cfgs, seeds)`,
which expands each base ExperimentConfig into one copy per seed via
`dataclasses.replace`. configs/experiments.py now generates
2 architectures x 5 seeds = 10 experiments (`_SEEDS = range(5)`).

scripts/aggregate_seeds.py aggregates a completed seed sweep into mean +/-
std bands:

    python scripts/aggregate_seeds.py <family_dir>

where <family_dir> is the directory holding the `seed=N/` run directories
for one architecture (e.g.
runs_arch_sweep/MODULAR/depth=1/width=128/init=1/wd=1). It loads each
seed's training_data_*.npz, and for every accuracy curve and every spectral
observable, interpolates onto a shared step grid before computing mean/std
across seeds. Interpolation (rather than an exact step join) is necessary
specifically for the spectral observables: the adaptive schedule in section
5 reacts to each run's own accuracy trajectory, so different seeds generally
log the spectrum at different steps. Output: one aggregate.png per
observable (shaded +/-1 std band) plus a combined seed_aggregate.npz, written
to <family_dir>/seed_aggregate/.

Design note: cross-seed variance (aggregate_seeds.py) and cross-probe
variance (section 4, within one run) are reported separately, not combined
into one pooled number. Properly combining them would need a mixed-effects
treatment of two different noise sources (probe sampling vs. training
stochasticity/init); reporting both separately is simpler and keeps it clear
which source of noise a given error bar reflects.


A PRE-EXISTING BUG FIXED ALONG THE WAY
-----------------------------------------
project_io/dir_making.py built output paths from task/init/weight_decay/seed
only -- it never included architecture (depth/width). Once seeds are swept
across multiple architectures (section 6), a depth=1 and a depth=2 run with
the same seed would have silently overwritten each other's checkpoints and
figures in the same output directory. Fixed by adding `depth=`/`width=` path
components (and identity.json fields) in `make_dirs()`/`_identity_dict()`.

Validated with a smoke test (modulus=7, tiny model, 60 steps, 2 seeds): full
train -> spectral snapshot -> plot -> checkpoint pipeline runs cleanly, the
adaptive schedule correctly enters/exits its dense phase, and

expected low-seed-count warning; production runs use 5).
